до секції «Що ти отримаєш» (#results).

## 1. Розпакування на Windows

1. Натисни правою кнопкою на ZIP → «Видобути все».
2. Відкрий вкладену папку svoye-v17.
3. Саме в ній лежать package.json, package-lock.json, app, public і scripts.
   Порядок файлів у Провіднику не має значення.
4. Збережи стару версію окремо, якщо вона ще потрібна.

## 2. Запуск на своєму комп'ютері

Потрібен Node.js версії 22.13.0 або новішої, разом із npm.
Встановлення залежностей потребує доступу до інтернету.

Відкрий Термінал у папці, де лежить package.json. На Windows можна
скористатися командним рядком (cmd), якщо PowerShell блокує npm.ps1.
Виконай по черзі:

```text
node --version
npm --version
npm run install:ci
npm run dev
```

Відкрий http://localhost:5173 або адресу, яку покаже термінал.
Щоб зупинити сайт, натисни Ctrl+C. Наступного разу достатньо npm run dev.

Перевір головну сторінку, /parents і /about; кнопку результату;
практичні проби й відображення на вузькому екрані.

## 3. Оновлення наявного репозиторію GitHub

1. У GitHub Desktop вибери свій репозиторій «svoye».
2. Fetch origin; якщо доступне Pull origin — отримай останні зміни.
3. Якщо є незбережені зміни або окремі доробки, спочатку збережи їх
   окремим комітом і перевір різницю: цей архів не об'єднує їх автоматично.
4. Через Repository → Show in Explorer відкрий кореневу папку репозиторію.
5. Скопіюй у неї ВМІСТ папки svoye-v17, зберігаючи структуру та приховані
   конфігураційні файли (.gitignore, .npmrc, .openai). Не створюй ще одну
   вкладену папку svoye-v17 у корені. Папку .git репозиторію збережи.
6. Перед заміною відмінних файлів перевір, чи немає у них власних або
   спільних новіших змін. За потреби об'єднай їх, а не замінюй повністю.
7. Переглянь зміни в GitHub Desktop, створи Commit і натисни Push origin.

Архів не містить Git-історії, node_modules, dist або локальних станів.
GitHub зберігає код; Push сам по собі не публікує сайт, якщо окреме
автоматичне розгортання ще не налаштоване.

## 4. Перенесення на інший хостинг

Проєкт використовує React, Vinext, Vite і Cloudflare Workers.
Для перевірки збірки після встановлення залежностей:

```text
npm run build
```

Ціль розгортання поточної конфігурації — Worker у dist/server
і клієнтські ресурси у dist/client. GitHub Pages не запускає цей
серверний проєкт без окремої адаптації до статичного експорту.
Перенесення на іншу платформу потребує сумісного середовища або
адаптації конфігурації; для Vercel/іншого Next.js-хостингу її слід
перевірити й змінити під обраний хостинг.

.openai/hosting.json містить ідентифікатор чинного Sites-проєкту;
це не секрет. Він збережений для можливості продовжити роботу із
цим самим сайтом. Не видаляй файл без адаптації vite.config.ts,
який його імпортує. Нове середовище не отримує автоматично домен,
налаштування доступу або платформні інтеграції ChatGPT.

D1 і R2 у поточному manifest не підключені. Архів не містить
експорту бази даних, хмарних налаштувань або облікових даних.
Майбутні кабінет, ШІ, Telegram-бот та календар у планах розвитку
не є реалізованими функціями цієї версії.

Версію й коміт звірено з Sites; усі вихідні файли взято з цього
коміту без змін. Перевірено відповідність package.json lock-файлу,
наявність ресурсів, цілісність ZIP та контрольні суми файлів.

Технічна довідка про проєкт — README.md; походження та SHA-256
кожного вихідного файла — ARCHIVE_INFO.json.
