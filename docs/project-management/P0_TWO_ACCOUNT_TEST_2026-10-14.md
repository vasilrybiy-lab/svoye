## B. Чого чекаємо від власника перед увімкненням тестувальника

1. Знайти **добровільного** повнолітнього учасника з окремим Telegram-акаунтом, який погодиться на один тестовий запис. За потреби використовувати інший власний акаунт. Учаснику пояснити, що це тест, і що бот попросить **власний Telegram-контакт** (номер телефону, збережений у Neon).
2. Передати учаснику посилання на **наявний** бот «Своє» через Telegram (не вигадувати username). Попросити надіслати лише **«Привіт, це тест»**. **Поки не натискати бронювання.**
3. Повідомити в робочому чаті ChatGPT, що тестер відправив нейтральне повідомлення, і приблизний час. За execution `Telegram Trigger` ідентифікувати **саме цього** user ID, не збираючи пароль, номер телефону чи скрин контактів.
4. **Лише після підтвердження належності ID та згоди** адресно оновити рівно **дві** allowlist-умови:
   - `Booking Request → Allowed Test User?`: `owner_id OR tester_id`;
   - `Telegram Assistant → Allowed Confirmation Test User?`: `owner_id OR tester_id`.
   Після node-config validation, read-back, перевірки зв'язків і публікації ОБОХ workflow зробити read-only preflight. **Не міняти** `T06 — Owner Link Sender Authorized?` або адресу admin notification. Залишити третіх осіб поза allowlist. Без ID нічого не публікувати.
5. Перевірити за read-only, що обраний час вільний в **особистому + консультаційному** календарях та Neon, і домовитися про 30-хвилинний слот. Для Telegram T−2h і T−1h обрати час з можливістю спостерігати обидва нагадування.

## C. Мінімальний реальний тест №1: Telegram-відеодзвінок

- **Клієнт** із другого Telegram-акаунта просить запис на погоджені дату/час і явно обирає **Telegram**.
- Бот перевіряє час, запитує **власний контакт тестера**, видає кнопку підтвердження. До підтвердження не казати «заброньовано».
- Після одного натискання клієнт **одразу** отримує confirmed з датою/форматом і поясненням, що link надійде за годину. У нього не має з'явитися адмін-сповіщення чи команда `/call`.
- У Neon одна `booking_requests.status='booked'`, один booked slot з **user_id другого клієнта**, одна Google Calendar-подія **без Google Meet**, відповідні start/end.
- **Власник** отримує окреме адмін-сповіщення, команду `/call <booking_uuid> `, і жодних клієнтських приватних повідомлень іншому користувачеві.
- Для перевірки T−2h **не створювати Telegram URL до першого нагадування консультанту**; коли воно прийде, створити call link, надіслати адміном `/call UUID https://t.me/call/<actual_slug>`. Відповідь бота — **збережено**, не «відправлено клієнту».
- До T−1h у клієнтському чаті **немає** URL; за T−1h він отримує **одне** повідомлення «нагадування + справжнє посилання» і у Neon `reminder_1h_sent_at` / `telegram_call_link_sent_at` заповнені. Наступний запуск scheduler **не дублює**.
- Якщо щось невизначене — **не повторювати confirm і /call**; спершу перевірити execution IDs, Neon і календар. Скасувати лише конкретну тестову подію після перевірки, звільнити slot й очистити test-only booking.

## D. Мінімальний реальний тест №2: Google Meet

- Інший 30-хвилинний слот, той самий **другий клієнт**, формат **Google Meet**.
- Клієнт отримує підтвердження **без URL** відразу після `booked`.
- Подія одна, Meet URL створено в Google; у Neon `booked` + `meet_link`. Консультант отримує адміністративне повідомлення з форматом і Meet-посиланням у свій чат.
- За T−1h клієнт отримує **один** Meet URL із нагадуванням. До того його в клієнтському чаті немає.
- Після PASS — адресно прибрати лише test booking/event, перевірити порожні слоти й відсутність дублів.

## E. Критерії PASS / FAIL та докази

| Критерій | PASS лише якщо |
| --- | --- |
| Авторизація | Дозволені тільки owner + 1 погоджений tester; третій акаунт не може створити або підтвердити booking. |
| Розділення ролей | Адмін-сповіщення та `/call` тільки owner; клієнтські повідомлення й link тільки tester. |
| Достовірність | Один `booked` у Neon, один слот, одна правильна Google-подія на кожну консультацію; жодного false confirmed. |
| Відкладена доставка | Підтвердження одразу, URL за T−1h/у погодженому короткому випадку, власнику T−2h якщо Telegram URL відсутній; жодних повторів. |
| Безпека та cleanup | Немає підміни адресата, повторного Google Create, секретів у чатах, тестових залишків після cleanup. |

**Докази записувати в протокол:** обидва анонімізовані ролі / час за Києвом, booking UUID (внутрішній, не публікувати контакт), виконання n8n по кожній стадії, факт Calendar event, query-result зі статусами Neon, повідомлення з часом і адресатом без телефонів/токенів, результати cleanup.

**Статус на момент створення:** PREPARED, **NOT EXECUTED**. Жоден другий акаунт не зареєстровано, ніяких production allowlist змін ще не виконано. Не відкривати публічний доступ до окремого рішення.
